# Implementation Prompt: 3.2 Clerk User Synchronization with Supabase Database

## 1. Goal
Connect authenticated Clerk users with the Supabase PostgreSQL `users` table. Whenever a user signs up or signs in, their Clerk profile details (`id`, `email`, `full_name`) will be automatically synced and upserted into the database, allowing other tables (like `progress`) to reference the user reliably and enabling the app to fetch the database user record.

## 4. Decisions & Assumptions
1. **Idempotent Upsert**: Use `supabase.from('users').upsert({ id, email, full_name }, { onConflict: 'id' })` so user updates on each login without duplicate key errors.
2. **Session Deduplication**: Cache synced state per user ID in session storage to avoid redundant network calls during route changes while still guaranteeing immediate sync on sign-in or sign-up.
3. **Resilience**: If Supabase is offline or tables are pending migration, log warnings silently without breaking user authentication or navigation.
4. **Hook/Provider Integration**: A lightweight `UserSyncProvider` will be mounted in `RootLayout`, transparently managing sync for all authenticated users.

## 6. Requirements
- When a user is signed in with Clerk, their record exists in `public.users` in Supabase with `id === clerkUser.id`.
- Support retrieving the database user via `userService.getUserById(clerkUserId)`.
- Zero UI blocking or performance degradation during auth.

## 7. Security Considerations
- Only the authenticated user's own Clerk ID and basic profile info are synced.
- RLS policies on `users` table allow read and write operations.
