# Implementation Prompt: 3.1 Supabase PostgreSQL Database Design & PostgREST CRUD Service

## 1. Goal
Design and establish the PostgreSQL database schema in Supabase for Vibelearn, generate idempotent SQL migrations and seed scripts, install and initialize `@supabase/supabase-js` using environment credentials (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`), and implement a clean, resilient PostgREST CRUD service layer for courses, modules, lessons, and user progress with fallback support.

## 2. Skills & Guidelines Consulted
- `AGENTS.md`: System design, server & client boundaries, environment configuration, roadmap alignment, verification checks, and theme fidelity.
- `docs/system_design/database.md`: ERD definitions (`users`, `courses`, `modules`, `lessons`, `progress`).
- `docs/superpowers/specs/2026-09-26-database-and-supabase-crud-design.md`: Approved database specification and CRUD architecture.
- `docs/roadmap.md`: Phase 3 tasks (3.1 Supabase connection, 3.2 Schema, 3.3 Migrations, 3.4 Seeding script, 3.5 Content endpoints / CRUD, 3.6 Progress tracking).

## 3. Code & Config Inspected
- `.env`: Contains `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_SUPABASE_PUBLISHABLE_KEY`.
- `docs/seed.ndjson` & `docs/videos.json`: Raw seed records for 10 courses, 40 modules, 120 lessons.
- `src/lib/mock-data.ts`: Existing seed dataset used for local fallback.
- `src/types/courses.ts`: Types for courses, modules, and lessons.

## 4. Decisions & Assumptions
1. **Direct PostgREST Client Architecture**: In alignment with user selection, we configure `@supabase/supabase-js` as the CRUD client reading from `.env`.
2. **Schema & Migration**: Provide `supabase/migrations/01_initial_schema.sql` containing DDL for `courses`, `modules`, `lessons`, `users`, `progress`, indexes, foreign keys, and RLS policies.
3. **Database Seeding**: Provide `scripts/seed-supabase.js` that parses `docs/seed.ndjson` and `docs/videos.json` and populates the Supabase tables over PostgREST. Also provide `supabase/seed.sql` for one-click SQL execution.
4. **Resilient Data Access**: The service layer (`src/services/course-service.ts`, `src/services/progress-service.ts`) attempts Supabase queries first; if the database is unreachable or empty, it gracefully falls back to local data so the site never breaks.
5. **Progress Persistence**: Upserts on `progress` use `UNIQUE(user_id, lesson_id)` allowing video resume timestamp updates and completion toggling.

## 6. Requirements
- Tables created: `courses`, `modules`, `lessons`, `users`, `progress`.
- RLS enabled with public read access on courses, modules, lessons, and anon/user read/write on progress.
- `@supabase/supabase-js` client reads `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`.
- CRUD methods provided for courses, lessons, and user progress.
- Clean integration with existing React app components and types.

## 7. Security Considerations

- Sensitive credentials remain protected in `.env` and `.gitignore`.
- Video IDs and text slugs are validated and sanitized.
