# Implementation Prompt: 2.9 Mobile Responsiveness & Lesson Video Switching Fix

## 1. Goal
1. Fix the lesson video player so that selecting any lesson in the curriculum sidebar or switching courses immediately mounts and plays the corresponding YouTube video using a keyed `<iframe>` (`key={`${course.id}-${activeLesson.id}-${activeLesson.youtubeVideoId}`}`) and synchronized active state, rather than remaining stuck on the initial Next.js video.
2. Ensure full mobile responsiveness on the Learning Page and Course Detail Page:
   - On mobile screens (`< lg`), make the curriculum sidebar collapsible with a dedicated toggle ("Course Curriculum") and position the video player prominently so learners can watch without excessive scrolling.
   - Ensure tap targets (buttons, links, module toggles) satisfy accessibility standards (minimum 44px).
   - Optimize the sticky bottom progress bar on mobile to remain sleek without occluding content.

## 2. Skills & Guidelines Consulted
- `AGENTS.md`: Section 3 ("adapting the layout sensibly: stack columns, collapse the lesson sidebar while keeping the desktop exact"), Section 6 (YouTube embed rules), Section 11 (strict theme tokens and no arbitrary styling).
- `docs/roadmap.md`: Task 2.9 ("Ensure mobile responsiveness across all pages").
- `DESIGN.md`: Standard semantic colors, radius tokens, and font scale.

## 3. Code & Data Inspected
- `src/pages/learning-page.tsx`:
  - `<iframe>` lacked a `key` prop, causing browsers/React to reuse the DOM element and fail to reload new YouTube videos when switching lessons.
  - Sidebar was placed directly before main content in flex-col on mobile, forcing the user to scroll through the entire curriculum before reaching the video.
  - Missing responsive collapse/expand controls for the curriculum on mobile screens.
- `src/pages/course-detail-page.tsx`:
  - Floating bottom progress bar needed responsive padding and sizing for small mobile viewports.
- `src/lib/mock-data.ts`: Confirmed all 10 courses have 120 unique YouTube video IDs.

## 4. Decisions & Assumptions
1. **Dynamic Iframe Keying**: Add `key={`${course.id}-${activeLesson.id}-${activeLesson.youtubeVideoId}`}` to the `iframe` in `LearningPage`.
2. **Synchronized Active Lesson State**: Use `selectedLessonId` local state alongside `searchParams` so clicks immediately switch the active lesson and force re-render.
3. **Sensible Mobile Layout for Learning Page**:
   - On desktop (`lg:flex-row`), preserve the exact layout from `docs 2/design/learning-page.png` (left sidebar 360px, right content area).
   - On mobile (`< lg`), show a mobile curriculum bar with an expand/collapse toggle ("Show Curriculum" / "Hide Curriculum" with lesson count and progress), allowing the learner to watch the video immediately while easily accessing the syllabus when needed.
   - Ensure action buttons ("Mark as Complete", "Previous", "Next Lesson") format smoothly on mobile with full tap targets.
4. **Course Resume in "My Learning"**:
   - Store the last viewed course in `localStorage`.
   - If `/my-learning` is opened without an ID, resume that course instead of always defaulting to Next.js.

## 5. Files to Touch
- `src/pages/learning-page.tsx`: Add keyed iframe, synchronized lesson selection, mobile curriculum toggle, and responsive layout adjustments.
- `src/pages/course-detail-page.tsx`: Fine-tune mobile padding and sticky progress bar.
- `docs/roadmap.md`: Mark task 2.9 as completed once verified.

## 6. Requirements
- Video immediately changes when any lesson in the curriculum sidebar is clicked.
- Navigating to any course displays that course's authentic video and lessons.
- On mobile devices (down to 360px), the learning page must be clean, readable, with no horizontal scrolling and an intuitive collapsible curriculum.
- Desktop layout must remain 100% faithful to the provided design reference.
