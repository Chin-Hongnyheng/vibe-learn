# 2.10 — Habits and Daily Logs (Supabase Schema, Seed, & API Integration)

## Goal

Provide a complete, production-ready solution for tracking learner habits and daily logs:
1. A standalone SQL migration & seed file (`src/lib/habits-schema.sql`) for easy execution in the Supabase SQL Editor.
2. A foreign-key relationship between `daily_logs` and `habits` with `ON DELETE CASCADE`.
3. Seed records demonstrating realistic learning habits and completed/pending daily logs.
4. TypeScript data contracts in `src/types/habits.ts`.
5. An API integration layer in `src/lib/api/habits.ts` using the Supabase client (`@/lib/supabase`).

---

## Architecture Boundary

| Entity | Read from Frontend | Write from Frontend | RLS Policy |
|---|---|---|---|
| `habits` | Allowed via anon client | Allowed via anon client | Permissive for development / user-filtered if `user_id` provided |
| `daily_logs` | Allowed via anon client | Allowed via anon client (upsert/insert) | Foreign key to `habits(id)` with `ON DELETE CASCADE` |

Note: `user_id` is an optional foreign key referencing `users(id) on delete cascade` so that habits can be either standalone or scoped to a logged-in Clerk user.

## Decisions & Assumptions

1. **Schema Design**:
   - **`habits`**:
     - `id`: `bigint primary key generated always as identity`
     - `user_id`: `text references users(id) on delete cascade` (nullable for guest/demo usage)
     - `title`: `text not null`
     - `description`: `text`
     - `category`: `text not null default 'Learning'`
     - `frequency`: `text not null default 'daily'`
     - `target_count`: `integer not null default 1`
     - `unit`: `text not null default 'times'`
     - `is_active`: `boolean not null default true`
     - `created_at`: `timestamptz not null default now()`
     - `updated_at`: `timestamptz not null default now()`

   - **`daily_logs`**:
     - `id`: `bigint primary key generated always as identity`
     - `habit_id`: `bigint not null references habits(id) on delete cascade`
     - `log_date`: `date not null default current_date`
     - `completed`: `boolean not null default false`
     - `count`: `integer not null default 1`
     - `notes`: `text`
     - `created_at`: `timestamptz not null default now()`
     - `unique (habit_id, log_date)`: Ensures at most one log entry per habit per calendar day.

2. **Seed Data**:
   - 4 diverse learning and developer habits:
     - "Watch 1 Course Lesson" (Learning, daily, target: 1 lesson)
     - "Code Practice & Projects" (Coding, daily, target: 30 minutes)
     - "Review Course Notes" (Learning, daily, target: 1 session)
     - "Deep Focus Study" (Focus, daily, target: 45 minutes)
   - Daily logs for today and yesterday showing both completed and pending entries.

3. **Client API Layer (`src/lib/api/habits.ts`)**:
   - `getHabits(userId?: string)`: Fetches all active habits.
   - `getHabitById(id: number)`: Fetches single habit with its recent logs.
   - `getDailyLogsForDate(date?: string)`: Fetches logs for a date (defaults to today).
   - `getHabitsWithTodayStatus(userId?: string)`: Joins habits with today's log to determine completion status.
   - `logHabit(habitId: number, completed: boolean, count?: number, notes?: string)`: Upserts a daily log for today.
   - `createHabit(habit)`: Creates a new habit.
   - `deleteHabit(id: number)`: Deletes a habit (cascading deletes logs automatically).

## Security Considerations

- Row Level Security (RLS) is enabled on both tables.
- Public/anon read & write policies allow demo/starter usage without blocking client calls.
- Foreign key constraint has `ON DELETE CASCADE` so deleting a habit leaves no orphan log rows.
- Unique constraint `(habit_id, log_date)` protects against race-condition duplicate logs.
