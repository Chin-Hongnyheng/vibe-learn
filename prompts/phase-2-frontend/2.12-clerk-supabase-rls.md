# 2.12 — Clerk → Supabase JWT Integration + Strict RLS

## Goal

Enable proper Row Level Security on `habits` and `daily_logs` so each user
can only read/write their own rows. This requires:

1. Connecting Clerk as a third-party auth provider in Supabase Dashboard.
2. Updating the Supabase client so it sends the Clerk JWT on every request.
3. Replacing the open RLS policies with user-scoped ones using `auth.jwt()->>'sub'`.
4. Ensuring `habits-schema.sql` stays in sync as the source of truth.

## Key Technical Facts

- Clerk user IDs are strings like `user_2abc` — NOT UUIDs.
- Supabase `auth.uid()` expects a UUID → DO NOT use it. Use `auth.jwt()->>'sub'` instead.
- `user_id` column in `habits` is already `text` — compatible.
- The modern approach (2025+) is Supabase Third-Party Auth with Clerk as provider.
  This replaces the old manual JWT template approach.
- The Supabase client needs to send the Clerk session token as Bearer on every request.

## Dashboard Steps (user must do manually — cannot be scripted)

### Step A — Clerk Dashboard
1. Go to https://dashboard.clerk.com → select your app
2. Left sidebar → Integrations → Supabase
3. Click "Connect" / "Enable" — Clerk will show you a "Clerk Domain" value (looks like `<app-slug>.clerk.accounts.dev`)
4. Copy that domain — needed for Step B.

### Step B — Supabase Dashboard
1. Go to https://supabase.com/dashboard → your project
2. Left sidebar → Authentication → Sign In / Providers
3. Scroll to "Third-Party Auth" section → Add provider → choose "Clerk"
4. Paste the Clerk Domain from Step A
5. Save.

### Step C — Update RLS policies (SQL to run in Supabase SQL Editor)
```sql
-- Drop old open policies
drop policy if exists "allow read habits" on habits;
drop policy if exists "allow insert habits" on habits;
drop policy if exists "allow update habits" on habits;
drop policy if exists "allow delete habits" on habits;
drop policy if exists "allow read daily_logs" on daily_logs;
drop policy if exists "allow insert daily_logs" on daily_logs;
drop policy if exists "allow update daily_logs" on daily_logs;
drop policy if exists "allow delete daily_logs" on daily_logs;

-- Strict user-scoped policies for habits
create policy "habits: select own" on habits
  for select using ((auth.jwt()->>'sub') = user_id);
create policy "habits: insert own" on habits
  for insert with check ((auth.jwt()->>'sub') = user_id);
create policy "habits: update own" on habits
  for update using ((auth.jwt()->>'sub') = user_id);
create policy "habits: delete own" on habits
  for delete using ((auth.jwt()->>'sub') = user_id);

-- Strict user-scoped policies for daily_logs (via habit ownership)
create policy "daily_logs: select own" on daily_logs
  for select using (
    exists (
      select 1 from habits h
      where h.id = daily_logs.habit_id
        and (auth.jwt()->>'sub') = h.user_id
    )
  );
create policy "daily_logs: insert own" on daily_logs
  for insert with check (
    exists (
      select 1 from habits h
      where h.id = daily_logs.habit_id
        and (auth.jwt()->>'sub') = h.user_id
    )
  );
create policy "daily_logs: update own" on daily_logs
  for update using (
    exists (
      select 1 from habits h
      where h.id = daily_logs.habit_id
        and (auth.jwt()->>'sub') = h.user_id
    )
  );
create policy "daily_logs: delete own" on daily_logs
  for delete using (
    exists (
      select 1 from habits h
      where h.id = daily_logs.habit_id
        and (auth.jwt()->>'sub') = h.user_id
    )
  );
```

## Code Changes (I implement these)

### 1. `src/lib/supabase.ts`
Replace static client with a factory that injects the Clerk JWT:
- Export the base `supabase` anon client (unchanged — used for public reads).
- Export a `createClerkSupabaseClient(getToken)` factory that wraps fetch to inject `Authorization: Bearer <clerk-token>`.

### 2. `src/pages/habits-page.tsx`
- Use `useAuth()` from `@clerk/clerk-react` to get `getToken`.
- Create a Clerk-aware Supabase client with `createClerkSupabaseClient`.
- Pass this client down to all habits API calls (update function signatures).

### 3. `src/lib/api/habits.ts`
- Add optional `client` parameter to each function (falls back to base `supabase` if not provided).
- This keeps backward compatibility for public reads (courses, etc.).

### 4. `src/lib/habits-schema.sql`
- Update RLS policy section to match the strict policies above (for documentation).
