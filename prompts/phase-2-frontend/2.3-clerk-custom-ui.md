# 2.3 — Clerk Custom UI for Sign-In and Sign-Up Pages

## Goal
Customize the UI and appearance of the Clerk Sign-In (`/sign-in`) and Sign-Up (`/sign-up`) pages to seamlessly match the Vibe Learn design system (`DESIGN.md` & `src/globals.css`). This includes custom Clerk `appearance` token mapping (emerald primary `#10B981`, slate neutrals, Inter & Playfair Display typography, 12px input/button radius, 16px card radius, soft elevation shadows), branded page wrapper layouts with logo and value propositions, and flawless light/dark mode compatibility.

## Skills and Guidelines Read
- `clerk-custom-ui`: Appearance customization using `appearance.variables`, `appearance.elements`, and `appearance.layout`.
- `AGENTS.md`: Section 1 (platform scope), 2 (loop rules), 3 (UI reproduction & strict tokens), 11 (strict system design & technology lock), and 12 (npm commands).
- `docs/system_design/frontend.md`: Rule 3 ("NO Custom Auth Logic: Do not build custom login forms or JWT management. Use Clerk's `<SignIn>`, `<SignUp>`, and `<SignedIn>` components strictly").
- `DESIGN.md`: Primary palette (Primary 500 `#10B981`, Primary 600 `#059669`, Primary 100 `#D1FAE5`), Slate neutral palette (`#0F172A`, `#334155`, `#64748B`, `#E2E8F0`, `#FAFAFC`), Typography (Playfair Display for display headers, Inter for UI), radii (12px inputs/buttons, 16px cards), and elevation shadows.
- `src/globals.css`: Theme variables (`--primary`, `--background`, `--card`, `--foreground`, `--border`, `--input`, `--ring`) for both `:root` and `.dark`.

## Inspected Code and Configuration
- `src/pages/sign-in-page.tsx`: Currently renders unstyled `<SignIn />` on `bg-[#FAFAFC]` (contains arbitrary hex).
- `src/pages/sign-up-page.tsx`: Currently renders unstyled `<SignUp />` on `bg-[#FAFAFC]` (contains arbitrary hex).
- `src/main.tsx`: `ClerkProvider` wraps `ThemeProvider` and `App`.
- `src/sections/navigationsection.tsx`: Uses `src/assets/logo.png` for Vibe Learn branding.
- `components.json`: Confirms shadcn/ui configuration with `neutral` base color and CSS variables.

## Decisions and Assumptions
1. **Clerk Appearance Architecture**:
   - Create a reusable appearance configuration module `src/lib/clerk-appearance.ts` exporting `getClerkAppearance(isDark: boolean)` and shared element styling classes.
   - Style Clerk's internal elements (`card`, `headerTitle`, `headerSubtitle`, `socialButtonsBlockButton`, `formButtonPrimary`, `formFieldInput`, `formFieldLabel`, `footerActionLink`, `identityPreview`, etc.) using semantic Tailwind classes (`bg-card`, `text-card-foreground`, `border-border`, `bg-primary`, `text-primary-foreground`, `rounded-md`, `rounded-lg`, etc.).
   - Configure `variables`:
     - `colorPrimary`: `#10B981` (Primary 500)
     - `borderRadius`: `0.75rem` (12px base radius)
     - `fontFamily`: `'Inter', -apple-system, BlinkMacSystemFont, sans-serif`
     - Dynamic background and text colors matching current theme.
2. **Page Wrapper & Branded Layout**:
   - Wrap `<SignIn>` and `<SignUp>` in a dedicated branded presentation layout in `src/pages/sign-in-page.tsx` and `src/pages/sign-up-page.tsx`.
   - Include Vibe Learn logo (`logo.png`), an ambient emerald glow effect behind the card (`bg-primary-500/10 blur-3xl`), and an encouraging brand header (`font-serif text-3xl font-bold`).
   - Replace arbitrary `bg-[#FAFAFC]` with semantic `bg-background text-foreground`.
   - Ensure responsive padding and centered alignment for mobile and desktop.
3. **Global ClerkProvider Integration**:
   - Update `src/main.tsx` to pass the base Clerk appearance to `<ClerkProvider>` so all Clerk components (including `<UserButton>` dropdowns and modals) adhere to the Vibe Learn theme.
4. **No Extra Packages**:
   - Strictly respect the Technology Lock in `AGENTS.md` by using Clerk's native `appearance` prop and existing Tailwind CSS without installing extra dependencies.

- `src/pages/sign-up-page.tsx`: Update with Vibe Learn branded layout and custom appearance.

## Requirements
1. Sign-In and Sign-Up components match Vibe Learn's visual tokens: emerald primary buttons (`#10B981`), rounded borders (12px inputs/buttons, 16px card), Inter font for body/inputs, and Playfair Display for display headings.
2. Form inputs have emerald focus rings (`ring-primary-500/20` and `border-primary-500`).
3. Fully functional in both light mode and dark mode, responding dynamically to the theme switcher in the navigation bar.
4. No arbitrary hex codes; strictly use semantic theme tokens and registered palette classes.
5. All auth redirects (`path="/sign-in"`, `signUpUrl="/sign-up"`, `signInUrl="/sign-in"`) remain intact and functional.

## Security Considerations
- `VITE_CLERK_PUBLISHABLE_KEY` remains the only client-exposed credential.
- No sensitive user credentials or tokens are handled outside Clerk's secure iframe/components.

## Acceptance Criteria
- Navigating to `/sign-in` renders a styled Vibe Learn sign-in experience.
- Navigating to `/sign-up` renders a styled Vibe Learn sign-up experience.
- Toggling dark mode in the header immediately updates the auth forms to dark slate backgrounds and light text.
- `npm run lint` and `npm run build` pass with zero errors.

## Checks to Run
- `npm run lint`
- `npm run build`
