# Implementation Prompt: 2.9 Lesson Video Switching & Course Player Fix

## 1. Goal
Fix the lesson video player on the Learning Page (`/courses/:id/learn` and `/my-learning`) so that clicking any lesson in the curriculum sidebar or navigating to any course (React, TypeScript, LLMs, Python, System Design, Postgres, DevOps, Security) correctly switches the active YouTube video and mounts the corresponding video player, rather than remaining stuck on the initial Next.js video.

## 2. Skills & Guidelines Consulted
- `AGENTS.md`: Playback stays on the site through YouTube embed; preserve component boundaries; strictly adhere to theme tokens and lint/build checks.
- `docs/system_design/frontend.md`: Clean React state management without cascading renders; resilient routing.

## 3. Code & Data Inspected
- `src/pages/learning-page.tsx`:
  - The `iframe` lacked a `key` prop (`key={`${course.id}-${activeLesson.id}-${activeLesson.youtubeVideoId}`}`). React reused the DOM element and browsers did not reload the iframe document when only `src` changed, causing the initial Next.js video to remain on screen.
  - `selectLesson` only called `setSearchParams` without explicit state synchronization, leading to potential stale active lesson indices.
  - `/my-learning` had no `id` param and always defaulted to `MOCK_COURSES[0]` (Next.js) instead of resuming the learner's last visited course.
- `src/lib/mock-data.ts`: Confirmed all 10 courses have 120 unique, valid YouTube video IDs (Next.js, React DevTools, TypeScript, LLM Tokens, RAG, Python, System Design, PostgreSQL, Docker, OWASP).

## 4. Decisions & Assumptions
1. **Dynamic Iframe Keying**: Add `key={`${course.id}-${activeLesson.id}-${activeLesson.youtubeVideoId}`}` to the `iframe` element. This forces React to unmount the previous iframe and mount a fresh player whenever the course, lesson, or video changes.
2. **Synchronized Active Lesson State**:
   - Maintain `selectedLessonId` state in `LearningPage`.
   - Update both `selectedLessonId` and `setSearchParams({ lesson: target.lesson.slug })` when a lesson is clicked in the sidebar or when Next/Previous is pressed.
   - Reset `selectedLessonId` when switching courses.
3. **Last-Visited Course Resume**:
   - Save the active course ID to `localStorage.getItem("lastVisitedCourseId")`.
   - When visiting `/my-learning` without an explicit `:id`, resume the last visited course (or default to course 1 if none is saved).

## 5. Files to Touch
- `src/pages/learning-page.tsx`: Add dynamic iframe keying, active lesson state synchronization, and course resume logic.

## 6. Requirements
- Clicking any lesson in the curriculum sidebar must immediately switch the YouTube player to that lesson's video.
- Navigating to any course (e.g. Course 2: React Performance Engineering, Course 3: TypeScript) must play that course's first lesson video (e.g. `Qwb-Za6cBws` for React DevTools) instead of Next.js.
- Next / Previous buttons must update the active lesson and video seamlessly.
- Breadcrumbs, notes, and key points must update in sync with the active lesson.

## 7. Security Considerations
- Keep `https://www.youtube-nocookie.com/embed/` URL structure.
- Sanitize video ID inputs.

## 8. Acceptance Criteria
- [ ] `iframe` in `LearningPage` has `key={`${course.id}-${activeLesson.id}-${activeLesson.youtubeVideoId}`}`.
- [ ] Clicking different lessons in the sidebar updates the YouTube video immediately.
- [ ] Navigating to `/courses/2/learn` or `/courses/3/learn` displays the respective course's videos and curriculum.
- [ ] `npm run lint` and `npm run build` pass with 0 errors.
